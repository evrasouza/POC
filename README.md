# BRP Public Websites Playwright Framework

This project is a TypeScript Playwright automation framework for BRP public websites. It starts small, with one homepage smoke test, while keeping the architecture ready for multi-brand and multi-locale validation across navigation, product discovery, forms, lead generation, shared components, localization, analytics, API calls, and visual checks.

The reference repository `evrasouza/mybrpV2` was used only for architecture cues: a clear top-level folder layout, strict TypeScript, Playwright configuration, custom fixtures, Page Object Model classes, utilities, linting, formatting, and maintainable npm scripts. This project does not copy its tests or application-specific logic.

## Installation

```bash
npm install
npx playwright install
```

## Brand Configuration

Brands live in `config/brands.ts`. Each brand has only the information needed to build URLs:

```ts
{
  id: 'canam-offroad',
  displayName: 'Can-Am Off-Road',
  origin: 'https://can-am.brp.com',
  productLinePath: 'off-road',
}
```

Can-Am Off-Road and On-Road use a product line path. Sea-Doo, Ski-Doo, and Lynx do not. That difference stays in configuration instead of being scattered through tests.

## Locale Configuration

Locale is dynamic. The selected country and language are read from command-line parameters first, then environment variables, then defaults.

Defaults:

```text
brand = canam-offroad
country = ca
language = en
```

Example locales include `ca/en`, `ca/fr`, `us/en`, `br/pt`, `de/de`, `fr/fr`, `no/no`, `fi/fi`, and `se/sv`. The framework does not assume every brand supports every locale.

## URL Generation

URLs are generated by `utils/url-builder.ts`.

```ts
buildUrl({
  brand: 'canam-offroad',
  country: 'ca',
  language: 'en',
  path: '/',
});
```

Result:

```text
https://can-am.brp.com/off-road/ca/en/
```

Sea-Doo example:

```ts
buildUrl({
  brand: 'seadoo',
  country: 'ca',
  language: 'en',
  path: '/',
});
```

Result:

```text
https://sea-doo.brp.com/ca/en/
```

## Selecting Another Brand or Locale

Command-line parameters take precedence over environment variables. The npm scripts use `scripts/run-playwright.mjs` to consume BRP-specific options before invoking Playwright, so these flags work without Playwright rejecting them:

```bash
npm test -- --brand=seadoo --country=ca --language=en
```

Locale shorthand is also supported:

```bash
npm test -- --brand=seadoo --locale=ca-en
```

Windows PowerShell environment variables:

```powershell
$env:BRAND='seadoo'; $env:COUNTRY='ca'; $env:LANGUAGE='en'; npm test
```

macOS/Linux environment variables:

```bash
BRAND=seadoo COUNTRY=ca LANGUAGE=en npm test
```

Concrete examples:

```bash
npm test -- --brand=canam-offroad --country=ca --language=en
npm test -- --brand=canam-onroad --country=ca --language=fr
npm test -- --brand=seadoo --country=ca --language=en
npm test -- --brand=skidoo --country=ca --language=en
npm test -- --brand=lynx --country=ca --language=en
```

## Adding Another Brand

Add a new entry to `config/brands.ts`:

```ts
'example-brand': {
  id: 'example-brand',
  displayName: 'Example Brand',
  origin: 'https://example.brp.com',
  productLinePath: 'optional-product-line',
}
```

Then add the new id to `BrandId` in `types/site.types.ts`. No tests should need to change.

## Adding Another Locale

No source change is required for a normal country/language URL:

```bash
npm test -- --brand=canam-offroad --country=br --language=pt
```

If a future brand has a non-standard locale format, keep that knowledge in the configuration or URL builder layer.

## Creating a New Page Object

Create a page class in `pages/` and extend `BasePage`:

```ts
import { BasePage } from './base.page.js';

export class ProductListingPage extends BasePage {
  async gotoListing(): Promise<void> {
    await this.goto('/vehicles');
  }
}
```

Add it to `fixtures/test.fixture.ts` when tests need convenient access.

## Creating a Reusable Component

Create shared UI components in `components/`:

```ts
export class NavigationComponent {
  constructor(private readonly page: Page) {}
}
```

Attach components to pages when they represent reusable page regions such as header, footer, cookie banner, navigation, dealer locator, or lead forms.

## Creating a New Test

Tests should describe behavior. Configuration determines where the behavior runs:

```ts
import { test, expect } from '../../fixtures/test.fixture.js';

test('homepage loads', async ({ homePage }) => {
  const response = await homePage.goto();
  expect(response?.ok()).toBe(true);
});
```

Avoid brand-specific duplicate tests unless the user experience genuinely differs.

## Initial Smoke Test

`tests/smoke/homepage.spec.ts` proves the framework works by:

1. Building the selected brand and locale URL.
2. Navigating to the public website.
3. Verifying the HTTP response succeeds.
4. Verifying the document body is visible.
5. Verifying the browser is on the expected hostname.
6. Checking for obvious application-level error text such as `404`, `500`, `not found`, or `server error`.
7. Printing the brand and locale under test.

The test intentionally avoids marketing-copy assertions so it can run across languages.
